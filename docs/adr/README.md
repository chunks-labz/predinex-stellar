# Architecture Decision Records (ADRs)

This directory contains Architecture Decision Records (ADRs) documenting significant design decisions for Predinex Stellar.

## When to write an ADR
Write an ADR when making a significant architectural decision that:
- Affects multiple components or systems
- Has long-lived consequences
- Is not easily reversible
- Establishes a pattern or convention that others will follow

Examples: data model changes, API contracts, security policies, technology choices, or workflow changes.

## ADR numbering
ADRs are numbered sequentially starting from 0000 (template) onwards. Use zero-padded 4-digit numbers.

## ADR template
Use [0000-adr-template.md](0000-adr-template.md) as the starting point for new ADRs.

## Status
Each ADR has a status:
- Proposed: Under review/discussion
- Accepted: Approved and in effect
- Deprecated: Superseded or no longer recommended
- Superseded: Replaced by another ADR (link to the replacement)
